# 结构化提问（elicitation）

信息不足时**一次问全，最多 8 问**；不要边算边挤牙膏。

## 1. 只问决策，不问参数

- ✅「你最多能承受亏多少？」
- ❌「你的 loss 参数填多少？」

用户给的是现实约束，参数由分析者换算。

## 2. 必问清单（按顺序）

| # | 问题 | 为什么问 | 缺省处理 |
|---|---|---|---|
| 1 | 你要决定的具体是什么？用一句话说 | 防止问题漂移 | 停下来，先定义 |
| 2 | 有哪几个选项？包括「什么都不做」 | 没有对照就没有决策 | 强制补「不做」 |
| 3 | 多久内要看到结果？ | 决定贴现与复盘节点 | 默认 90 天并标注 |
| 4 | 什么算成功？要可验证 | 防止事后改标准 | 追问到可量化 |
| 5 | 最坏情况下，你能承受损失多少？ | 破产线 | 必须给数字 |
| 6 | 同类事情，你或别人过去做成过几次？ | 基准率 | 没有就 `UNKNOWN` |
| 7 | 你手上支持/反对它的证据各有哪些？来源是什么？ | LR 输入 | 逐条登记来源 |
| 8 | 失败了你会怎么止损？ | 停止规则 | 默认「预算 30% 时复盘」 |

## 3. 「我不知道」怎么处理

不要替用户编，也不要停在「无法分析」。给三个工具：

1. **锚定区间**：「比 10% 高还是低？比 50% 呢？」→ 得到区间而非点值。
2. **参考类替换**：想不起自己的数据，就找同类公开数据；找不到就写 `UNKNOWN`。
3. **等价问题**：「如果必须押 100 块，你押哪边？赔率多少？」→ 反推概率。

## 4. 基准率的问法

```
参考类 = 时间 + 地域 + 人群 + 领域 + 规模
例：2022–2025 年，中国，个人，内容账号，启动成本 <5 万
```

- 参考类太宽 → 先验不可靠
- 参考类太窄 → 样本量不足
- 两者都要在结论里写出来

## 5. 证据登记表

| 字段 | 说明 |
|---|---|
| 来源 | 链接 / 报告名 / 「自己的实测」 |
| 类型 | 数据 / 案例 / 观点 / 传闻 |
| 独立性 | 是否与其他证据同源 |
| 方向 | 支持 / 反对 |
| 强度 | 强 / 中 / 弱（映射到 LR 区间） |
| 可靠性 | 0–1 |

**同源证据合并**：同一份报告被十家媒体转载，算 1 条。

## 6. 尝试的定义

追问三件事，缺一不可：

1. 一次尝试具体是什么动作？
2. 两次尝试之间，成功概率会不会变？（会 → 相关性高）
3. 两次尝试之间要花多少钱/时间？

## 7. 预注册（看结果之前）

在算出任何数字之前，先让用户确认：

- 排序规则：EV / 效用 / MCDA
- Go 的最低成功率与最低 EV
- 最大损失上限
- 破产概率上限
- 复盘节点

## 8. 常见提问错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 「你觉得成功率多少？」 | 得到拍脑袋点值 | 改成区间 + 锚定 |
| 一次问 20 个问题 | 用户放弃 | 合并成 8 个决策问题 |
| 用「行业平均」填空 | 假精确 | 写 UNKNOWN |
| 只问收益不问损失 | 低估风险 | 必问最大损失 |
| 不问「什么都不做」 | 高估行动价值 | 强制加入对照 |
